# Connect Supabase PostgreSQL to VS Code with SQLTools

This guide walks you through connecting your Supabase PostgreSQL database to Visual Studio Code using the **SQLTools** extension.

---

## 1. Install the VS Code Extensions

1. Open VS Code.
2. Press **Ctrl + Shift + X** (or **Cmd + Shift + X** on macOS) to open Extensions.
3. Search for **SQLTools** (by *Matheus Teixeira*) and click **Install**.
4. Search for **SQLTools PostgreSQL/Cockroach Driver** (by *Matheus Teixeira*) and click **Install**.
5. Once installed, the **SQLTools** icon (database cylinder) will appear in the VS Code Activity Bar on the left.

---

## 2. Retrieve Your Supabase Database Credentials

1. Go to the [Supabase Dashboard](https://supabase.com/dashboard) and open your project.
2. In the left navigation, click on the **Project Settings** (gear icon).
3. Under Configuration, select **Database**.
4. Scroll down to the **Connection parameters** / **Connection string** section.
5. Supabase offers two connection modes:
   - **Direct Connection** (Default Port: `5432`) — Best for persistent client tools like SQLTools.
   - **Connection Pooler** (Supavisor, Port: `6543` / `5432`) — Best for serverless applications or IPv4 networks requiring pooling.

You will need the following details:
- **Host**: e.g., `db.<project-ref>.supabase.co` (Direct) or `aws-0-<region>.pooler.supabase.com` (Pooler)
- **Port**: `5432` (Direct / Session Pooler) or `6543` (Transaction Pooler)
- **Database**: `postgres`
- **Username**: `postgres` (Direct) or `postgres.<project-ref>` (Pooler)
- **Password**: The database password you configured when creating the project.

---

## 3. Create a Connection in SQLTools

### Method A: Connect Using Server and Port (Recommended)

1. Click the **SQLTools** icon in the VS Code sidebar.
2. Under the **Connections** panel, click **Add New Connection** (or the `+` icon).
3. Select **PostgreSQL** from the database list.
4. Fill in the connection form:

| Field | Value | Notes |
|---|---|---|
| **Connection name** | `Supabase PostgreSQL` | Custom label for this connection |
| **Connection group** | Leave blank | Optional |
| **Connect using** | `Server and Port` | Standard mode |
| **Server Address** | `db.<project-ref>.supabase.co` | Or your pooler host (e.g. `aws-1-ap-southeast-2.pooler.supabase.com`) |
| **Port** | `5432` | Use `6543` if using transaction pooler |
| **Database** | `postgres` | Default Supabase database name |
| **Username** | `postgres` | Or `postgres.<project-ref>` if using pooler |
| **Use password** | **Ask on connect** or **Save password** | Your Supabase database password |

5. Under **Connection Options**:
   - Check **Use SSL**
   - Set SSL Method to `Require` or `Enable`
6. Click **Test Connection** to confirm connectivity.
7. Click **Save Connection**.

---

### Method B: Connect Using Connection String (URI)

If you prefer pasting the URI directly from Supabase:

1. In Supabase Dashboard → **Project Settings** → **Database** → **Connection string**, select **URI**.
2. Copy the URI string:
   ```text
   postgresql://postgres:[YOUR-PASSWORD]@db.[YOUR-PROJECT-REF].supabase.co:5432/postgres
   ```
   *(Or for connection pooler)*:
   ```text
   postgresql://postgres.[YOUR-PROJECT-REF]:[YOUR-PASSWORD]@aws-0-[REGION].pooler.supabase.com:6543/postgres
   ```
3. In SQLTools, click **Add New Connection** → **PostgreSQL**.
4. In **Connect using**, select **Connection String**.
5. Paste the URI into the **Connection String** field (replace `[YOUR-PASSWORD]` with your actual password; ensure any special characters in the password are URL-encoded).
6. Click **Test Connection** and then **Save Connection**.

---

## 4. Explore and Query Your Database

1. In the SQLTools sidebar, click on `Supabase PostgreSQL` and select **Connect**.
2. Expand the connection tree:
   - **Databases** → `postgres`
   - **Schemas** → `public` → **Tables**
3. You will see the DocuMind application tables:
   - `documents`
   - `chat_messages`
   - `approvals`
   - `feedback`
   - `audit_events`
4. Click **New SQL Query** to write queries, inspect embeddings metadata, or view audit logs directly from VS Code.
